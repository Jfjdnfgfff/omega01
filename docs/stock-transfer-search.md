# البحث في تحويل المخزون — فهرس سريع وكودبار في نافذة «تحويل بضاعة بين المخازن»

## المشكلة

نافذة **تحويل بضاعة بين المخازن** كانت تعرض قائمة منسدلة فقط:

1. مسح كامل مصفوفة `products` عند كل فتح للنافذة أو تبديل لاتجاه التحويل
   (`filter` + بناء HTML لكل الخيارات)؛
2. **لا يوجد أي بحث**: لا بالكتابة ولا بالكودبار — المستخدم يمرّر القائمة
   يدوياً ليجد المنتج، وهي مؤلمة خاصة مع مئات المنتجات.

## الحل

### 1) زر الكودبار + البحث بالكتابة

أصبح حقل اختيار المنتج يتبع نمط البحث المعتمد في بقية التطبيق (مثل نقطة
البيع POS):

| العنصر | المعرّف | الوظيفة |
| --- | --- | --- |
| مربع البحث | `transferProductSearchInput` | بحث حيّ أثناء الكتابة بالاسم أو الكودبار |
| زر الكودبار | `openBarcodeCamera('transfer_search')` | مسح الكودبار بالكاميرا → تحديد المنتج فوراً |
| زر المسح | `clearTransferProductSearch()` | إفراغ البحث وإعادة القائمة الكاملة |
| القائمة | `transferProductSelect` | نتائج البحث (نفس حقل الإرسال السابق) |
| سطر الحالة | `transferSearchStatus` | عدد النتائج / «تم تحديد» / سبب عدم الأهلية |

- **Enter** يحدّد النتيجة الوحيدة فوراً (مناسب لقارئ الكودبار المكتبي الذي
  يرسل الكود ثم Enter).
- **مطابقة كودبار دقيقة** تحدّد المنتج فوراً حتى بدون Enter.
- كودبار موجود لكن **غير قابل للتحويل** (كميته صفر أو في المخزن الآخر) يعرض
  سبباً واضحاً: «نفدت كمية [...]» أو «موجود في Stock 1 فقط — بدّل اتجاه
  التحويل أولاً».

### 2) الفهرس (`src/transfer-product-index.js`)

الملف يبني فهرساً في الذاكرة **مرة واحدة لكل تغيّر في البيانات** للمنتجات
القابلة للتحويل فقط (الموجودة في المخزن المصدر وفيها كمية > 0):

| الحقل | المحتوى | الاستخدام |
| --- | --- | --- |
| `entries` | المنتجات بترتيب المصدر مع نص بحث مُطبَّع مسبقاً | العرض والبحث |
| `byId` | `id → entry` | وصول فوري `O(1)` |
| `byBarcode` | كودبار مُطبَّع → entry | مطابقة الكودبار الدقيقة `O(1)` |

- **التطبيع**: يُطبَّق على الفهرس وعلى استعلام المستخدم معاً (حذف التشكيل
  والتطويل، توحيد `آ أ إ ٱ → ا` و`ى → ي` و`ة → ه`، توحيد الأرقام
  العربية/الفارسية، أحرف لاتينية صغيرة). البحث بأكثر من كلمة يستخدم
  **AND**: كل الكلمات يجب أن توجد.
- **الكودبار الدقيق** يُعاد وحده فوراً — سلوك مثالي للمسح بالكاميرا
  (`transfer_search`) أو بقارئ الكودبار.
- **إبطال الفهرس**: `transferProductsSignature()` تحسب بصمة
  `العدد:الموقع:هاش` فوق معرّف وكمية وموقع وباركود واسم كل منتج،
  و`createTransferProductIndexer()` يعيد البناء فقط عند تغيّر البصمة أو
  اتجاه التحويل. أي بيع أو تحويل أو تعديل منتج ينعكس تلقائياً.

الوحدة نقية بالكامل (بلا DOM) وتُختبر بـ `node --test`.

## الواجهة

- البحث حيّ (debounce 120ms) عبر `handleTransferProductSearchInput`.
- `handleTransferProductSearch(query, isEnter)` يعبّئ القائمة من الفهرس
  ويحدّد المنتج عند المطابقة الدقيقة أو عند Enter بنتيجة واحدة.
- تبديل اتجاه التحويل (`من مخزن` / `إلى مخزن`) يعيد التصفية من المخزن
  المصدر الجديد، والبحث الحالي يبقى مطبَّقاً.
